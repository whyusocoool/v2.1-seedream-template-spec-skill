# Seedream Skill 内置 Prompt 知识与执行指南

知识版本：2026-09-10.1。本文件随 Skill 一同打包。日常 DEFINE、FIT、TUNE 及 Prompt 审查直接读取本文件，不访问网页。相同上下文已加载且未变更时直接应用；上下文缺失时从 Skill 的 `references/` 目录重新读取。

来源：[Seedream 4.0-5.0 提示词指南](https://docs.volcengine.com/docs/82379/1829186?lang=zh)。2026-09-10 已读取官方正文；页面标示更新时间为 2026-05-11 17:10:19，列明适用 Seedream 4.0、4.5、5.0 lite。以下为提炼后的操作知识，不是原文全文，也不证明具体入口开放全部能力或任何模板已测试成功。URL 仅用于维护溯源，不是日常执行依赖。

## A. 官方建议的结构化提炼

| ID | 适用条件 | 编写动作 | 检查什么 |
| --- | --- | --- | --- |
| S01 | 所有任务 | 用连贯语言说明对象、动作和环境，再补充必要外观要求 | 名词关系是否清楚，是否只有碎片标签 |
| S02 | 有明确用途 | 说明输出类型及用途，例如海报、图标或产品效果图 | 读者是否知道要生成哪种成品 |
| S03 | 风格要求明确 | 使用足够具体的风格描述；实际可带图时可以指定风格参考 | 风格词是否有区分力，引用的图是否实际提交 |
| S04 | 图片包含指定文字 | 把要渲染的文字置于双引号内，并指明其角色 | 是否区分画面文字与给模型的指令 |
| S05 | 编辑已有图像 | 指明编辑对象、操作及要保持的部分 | 是否用模糊“它”指代多个对象，是否遗漏保留要求 |
| S06 | 细节丰富的文生图 | 清楚表达必要细节及其关系，去掉重复修饰 | 简洁是否误删要求，详细是否变成同义堆叠 |
| S07 | 知识、图表、教学内容 | 使用准确术语，说明呈现形式和版式 | 知识内容和视觉组织是否均有说明；正确性仍需检查 |
| S08 | 对象难以用文字定位 | 若运行流程允许，可利用实际输入图中的框线、箭头或涂画指示区域 | 标记是否真实存在；不要凭空写“红框处” |
| S09 | 参考图生成 | 分别写明从参考中保留什么，以及新图要表现什么 | 避免只写“照着参考图生成”而不区分借用与变化 |
| S10 | 草图或原型转效果图 | 指明目标成品、应沿用的结构；草图文字有约束意义时明确说明 | 输入是否清楚，关键布局与文字说明是否被正确使用 |
| S11 | 多图输入 | 为每张图分配对象与用途，说明替换、组合或迁移方向 | 图号是否和上传顺序一致，身份图与风格图是否混淆 |
| S12 | 多图输出 | 明确组图需求或张数，描述各张内容及共同要求 | 是多张图还是单张拼版；实际入口设置是否支持 |

官方建议强调清晰与精确，不给出本 Skill 旧有的“120-280 中文字”硬要求，也没有要求所有任务使用同一种句子顺序。复杂画面可以写长；不要为达成长度目标删除有效信息。

## B. 按任务选择模块

先依据实际运行输入和输出选择，可组合，不要求全部启用。黄金参考图用于 DEFINE 分析，不等于上线时一定传给 Seedream。

| 模块 | 选择条件 | 应用知识 | 内置写作骨架（非官方固定句式） |
| --- | --- | --- | --- |
| 文生图 | 运行时无图片 | S01-S04、S06；知识图加 S07 | 生成何种成品 → 对象与关系 → 场景与必要表现 → 指定文字 |
| 局部编辑 | 改输入图的局部内容 | S05；确有标记时加 S08 | 修改哪一处 → 增/删/替换/变化 → 保持什么 |
| 参考生成/风格转换 | 借用输入图的身份、外观或款式 | S03、S09 | 保留哪些特征 → 转成什么 → 新画面如何组织 |
| 草图转成品 | 输入平面图、线稿或原型 | S10，按需 S04/S07 | 目标成品 → 遵循哪些位置/比例/文字 → 如何呈现 |
| 多图组合 | 实际输入多张图片 | S11，叠加对应生成/编辑模块 | 图1负责什么、图2负责什么 → 组合关系 → 输出要求 |
| 组图 | 确实输出多个文件/多张图 | S12，叠加基础模块 | 张数 → 每张内容 → 跨图共同要求 |

自拟示例：
- 文本：“设计一张植物展海报，中央是一株蕨类，标题为 \"雨林来信\"，标题位于植物下方。”
- 编辑：“将画面左侧人物的外套改成深蓝色，保留其面部、姿势及背景。”
- 多图：“保留图1人物的面部特征，采用图2的纸艺表现，生成单张半身肖像。”

以上只解释句式，不作为模板默认内容，也没有真实生图验证。

## C. 与 DEFINE 五类和 Rule 的衔接（本 Skill 约定）

| Rule 分类 | 指南帮助解决什么 | 不能替代什么 |
| --- | --- | --- |
| 内容与保留 | 指代对象、文字引号、修改与保留的表达 | 不能证明哪些内容是 UX 想保留的 |
| 形态与组织 | 关系描述、草图结构、多图职责的表达 | 不能把写清位置当成实际布局正确 |
| 视觉表现 | 精准风格词、可见表现与参考图的结合 | 不能把风格词直接变成评分依据 |
| 输入适配 | 选择任务模块，描述条件下的变化与保留 | 不能从几张输出图推定适配已验证 |
| 成品可用性 | 明确输出用途、文字和组图形式 | 文件尺寸、可读性与事实准确性仍需检验 |

候选要求先依据参考图、使用目标筛选，再用指南判断表达方法。指南不决定 MUST/PREFERRED；难以表达的必要要求保留并标记未验证，不为迁就 Prompt 删除它。

## D. 编写、修改与审查步骤（本 Skill 约定）

1. 读取本指南，记录知识版本、目标模型和启用的任务模块。
2. 选取当前目标 Rule；区分必须保留的目标、允许变化和实际可用输入。
3. 依据适用 S 编号写自然语言。允许用“摄影”“水彩”等概念帮助生成，但仍按可见标准验收。
4. 指定文字加双引号；多图明确职责；编辑写清对象与保留范围。不要给纯文生图添加不存在的参考图或标记。
5. 建立 Prompt–Rule 多对多映射。CONFIG、REFERENCE、UNVERIFIED 分别记录实现方式；映射不是实现成功证明。
6. 修改时记录目标 Rule、修改假设、版本和完整 Prompt；去掉矛盾与重复，不机械套用固定长度或句序。没有要求的细节不自行添加。
7. 测试人员自主运行和优化；依据输出检查目标改善与其他 Rule 退步。AI 审查时也使用本指南，不接管每次实验，不悄悄改写测试文案。

只在已有目标或反复失败证据支持时加入负向约束；参考图未出现某物，不自动意味着禁止生成。纯粹“高质量”“高级”等词不能替代具体要求。这是本 Skill 的编写取舍，不标作官方禁词清单。

## E. Prompt 提交前检查

- 任务模块是否匹配实际输入？黄金图是否被错误当成运行时输入？
- 对象、关系、修改方向和保留部分是否明确？
- 指定文字是否准确、加引号且有位置或角色？
- 风格和细节是否支持目标，没有互相冲突？
- 多图职责、组图张数与实际入口是否一致？
- 每条重要要求是否有表达或其他实现记录，没有因难表达而丢失？
- 是否记录了变化与需要复测的 Rule，而非宣称遵循指南即可成功？

## F. 本地知识与维护

日常执行无需联网，不把“打不开官网”当作暂停 DEFINE 或调优的原因。未知版本/能力记录为未覆盖，使用可适用的通用知识，不自动扩展能力、不擅自切换模型。用户明确要求更新知识或版本专项核对时，再联网维护本文件并记录新版本、来源日期和变更。

在现有 promptGuideReview.reviewNote 中记录本地知识版本、任务模块及使用的 S 编号，不要求新表单。常规执行 sourceStatus 使用 LOCAL_ONLY，意为本轮应用本地知识，不否认知识曾来自官方正文；OFFICIAL_VERIFIED 仅用于本轮实际完成官方核对的维护情形。

向测试交付本文件及当前任务的适用要点；官方 URL 只作溯源。DEFINE 初版仍为 Prompt 0.0，后续版本与既有流程一致。原样导出不是 Prompt 修改，CALIBRATE 后不因此重新开启调优。
