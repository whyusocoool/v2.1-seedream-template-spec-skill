# Seedream Template Spec v2：DEFINE 与 Rules 规范

> 修订2：新输出以 [review-output-v2.md](review-output-v2.md) 为准：初版允许待规则确认，MUST通过/不通过，固定紧凑报告，6/6/4材料建议。以下旧评分/计划/交付布局仅供旧数据兼容，不覆盖修订2。

留档日期：2026-09-10。规范修订：1。适用数据版本：specVersion 0.4。

## 1. 范围与事实边界

本规范记录本次讨论确定的五类分组、固定遍历、要求筛选、粒度控制、MUST/PREFERRED 和 Seedream 指南使用机制。它是可执行的设计方案，不是经真实 Seedream 或独立评分者实验验证的分类标准。

已确认：分类不等于 Rule；分类可有零条或多条 Rule；完整遍历必须有记录；要求须经过筛选；保留 MUST/PREFERRED；测试人员主导 Prompt 调优；任何 Prompt 编写、修改、审查均应用 Seedream 指南。

实施约定：以下子项编号、JSON 字段、六种去向、schema 0.4 和报告布局用于把约定落地，并非此前逐字确认的术语。保留原有 2/1/0 评分、FIT/TUNE 测试计划、后续 UX Review、版本与回归机制；本次不重设出图数量、发布阈值或整个 CALIBRATE/RELEASE 流程。

五类服务于人与测试的沟通。AI 可以使用其他观察方法，但正式遍历记录必须覆盖此表。完整记录证明检查项有去向，不能证明视觉判断正确。

## 2. 角色与权威来源

- UX：提供参考图，确认必须保留、允许变化和使用范围；处理真正涉及目标的争议。
- GPT：遍历参考图，提出候选要求、判断依据和评分标准，编写初版 Prompt，生成交付；按需辅助诊断。
- Seedream：执行测试人员提交的 Prompt 和实际运行配置，生成图像。
- 测试人员：对照规则卡试跑、判断偏差、自主修改 Prompt、复测、记录结果；不必每轮等待 GPT 优化。
- 测试人员可以改变表达方式，不能自行改变验收目标。AI 不能为让结果通过而删除 MUST 或放宽评分。

目标依据按来源记录：参考图可见证据、UX 明确要求、推断。推断必须标明；共现频率不能直接证明 UX 意图。没有真实确认时不得填写已确认，也不能把测试 fixture 中的模拟确认当作用户决定。

## 3. 五类与固定遍历表

每个子项至少有一条记录；同一子项有多个发现时逐条记录，不用一个“已覆盖”掩盖不同去向。观察位置用参考图 ID 加可辨认区域描述，必要时增加裁切图。看不清不补全。

### C1 内容与保留

问题：输出该有什么，输入里的什么必须保留？排除位置、风格化形状和表面表现。

| 编号 | 检查项 | 观察或判断内容 |
| --- | --- | --- |
| C1.01 | 对象与数量 | 必要对象、对象数量、对象之间的语义关系；不判断二维位置 |
| C1.02 | 必要部件 | 必须存在的部件、符号和识别线索；不判断形状比例 |
| C1.03 | 文字与符号内容 | 实际字符、符号含义、内容准确性；不判断字体位置或可读尺寸 |
| C1.04 | 身份与特征保留 | 输入到输出需保留的身份或标志特征；无输入证据时标为推断 |
| C1.05 | 内容增删 | 是否需要增加、移除或替换内容；不能把参考图中未出现自动转成禁止项 |

### C2 形态与组织

问题：内容以什么形状、姿态和空间关系出现？排除色彩、边界过渡和制作来源。

| 编号 | 检查项 | 观察或判断内容 |
| --- | --- | --- |
| C2.01 | 比例与轮廓 | 部件比例、对象可见轮廓、圆角或转折；边缘模糊归 C3.03 |
| C2.02 | 姿态 | 可见部件朝向、姿势和动作关系；不推断不可见部件 |
| C2.03 | 位置与尺度 | 对象在画布的位置、占比和对象间相对大小 |
| C2.04 | 间距与对齐 | 间距、对齐、基线及偏移 |
| C2.05 | 遮挡与层次 | 可见重叠、包含、前后线索；不将深度推断写成确定物理事实 |
| C2.06 | 重复排列 | 单元重复、行列、步距、交替或允许的不规则性 |
| C2.07 | 裁切与留白 | 边缘裁切、空区分布、边距；同一完整性要求不在 C5 重复评分 |

### C3 视觉表现

问题：已确定的内容和结构呈现怎样的外观？排除内容准确性与布局。材质、摄影、绘画来源只能作为表现解释，不能断言真实制作过程。

| 编号 | 检查项 | 观察或判断内容 |
| --- | --- | --- |
| C3.01 | 色彩关系 | 主要色域、饱和程度、区域间色彩差异与允许配色变化 |
| C3.02 | 明暗与体积线索 | 渐变、亮暗区域、投影或反射候选；不反推精确灯位、镜头或工艺 |
| C3.03 | 边界与描线 | 清晰/渐变过渡、描边、断续、毛边；轮廓几何归 C2.01 |
| C3.04 | 表面痕迹 | 颗粒、笔触、斑驳、纤维等可见痕迹；注明分析尺度和可见性 |
| C3.05 | 媒介表现线索 | 支持纸艺、拼豆、黏土、水彩等整体外观的组合线索；引用前述事实，不重复计分 |
| C3.06 | 细节简化方式 | 细节保留密度、平面化、概括方式；跨输入复杂度的条件策略归 C4.02 |
| C3.07 | 图形与字形外观 | 字形或图标的描线、填充与风格特征；内容归 C1.03，位置归 C2，可读性归 C5.01 |

不另设“写实程度”总分。其必要要求落到具体形态、明暗、边界或简化方式。若“实体感”需作为完整 Rule，必须定义必要条件与辅助证据。

### C4 输入适配

问题：允许的输入发生变化时，模板应该如何响应？这是条件行为，不能仅凭几张输出参考图断言已验证。

| 编号 | 检查项 | 观察或判断内容 |
| --- | --- | --- |
| C4.01 | 多寡适配 | 单个/多个对象或单图/多图时的处理；只覆盖声明支持的范围 |
| C4.02 | 复杂度处理 | 复杂输入如何简化，简化时引用哪些保留要求 |
| C4.03 | 横竖幅适配 | 输入或输出比例变化时如何重排、缩放、裁切 |
| C4.04 | 文字长度适配 | 文本变长后的换行、缩放或版面策略；无文字输入时可不适用 |
| C4.05 | 背景与输入差异处理 | 不同背景、遮挡或输入质量的处理策略和支持边界 |

适配 Rule 描述“如果……则……”，引用 C1/C2/C3 的固定要求，不重新定义它们。它的独立评分只判断条件响应，不再次给被引用要求加分。

### C5 成品可用性

问题：结果是否满足已约定用途？仅有具体用途依据时保留，不自动追加泛用质量清单。

| 编号 | 检查项 | 观察或判断内容 |
| --- | --- | --- |
| C5.01 | 可读性 | 在约定展示尺度下能否读出文字；不重复检查原文正确性 |
| C5.02 | 必要内容完整性 | 交付时是否缺页、缺项或关键内容不可用；已由 C1/C2 覆盖则引用并合并 |
| C5.03 | 可辨识度 | 使用场景需要的辨认条件；已被身份保留 Rule 覆盖则不另计分 |
| C5.04 | 用途相关缺陷 | 只有妨碍约定用途的具体缺陷才成为候选，不能写“没有任何瑕疵” |
| C5.05 | 尺寸与输出形式 | 约定尺寸、比例、透明输出等；文件事实优先用工具验证，不由视觉模型猜测 |

## 4. 每个发现必须有一个去向

| 去向 | 含义 | 必须记录 |
| --- | --- | --- |
| RULE | 值得独立判断的模板要求 | Rule ID、支持依据、保留理由 |
| EVIDENCE | 某 Rule 的判断依据或已被覆盖 | 目标 Rule ID、为什么不独立计分 |
| OMIT | 不重要 | 已观察但不值得形成Rule：偶然特征、允许变化、重复覆盖或无用途价值等具体理由 |
| NOT_APPLICABLE | 无关 | 为什么该子项与这个模板的输入、输出或用途没有关系 |
| UNOBSERVABLE | 无法可靠判断 | 模糊、遮挡、缺输入对照等缺失条件 |
| PENDING_UX | 存在影响目标的歧义 | 需要 UX 判断的具体选择，不预填答案 |

UNOBSERVABLE 不等于缺失或不适用。辅助细节看不清可以继续；若影响核心验收，则记录为待 UX 解决的问题。PENDING_UX 未解决时可以保留草稿，但不能交付为已确认的正式标准。

## 5. 筛选、拆分与停止

先筛选是否值得保留，再决定是否独立成条，最后分配优先级。检查顺序：

1. 是否服务已确认的模板目标或用途？无关细节不保留。
2. 是否有参考图或 UX 依据？推断写明，参考图共现不等于必需。
3. 特征变化是否影响模板效果或用途？没有实质影响，不升级为要求。
4. 是否已被已有 Rule 覆盖？合并或作为依据，禁止重复计分。
5. 是否可独立判断且值得单独跟踪？是则 RULE，否则 EVIDENCE。

拆成两条 Rule，需同时满足：A 成功/B 失败有清楚意义；测试有必要分别优化或记录；两条不是用同一现象重复评分。典型例子：“文字原文正确”与“文字不遮挡人物”可以分别判断。

一条完整媒介要求可以有多个观察线索，但必须指明哪些是必要条件、哪些是辅助证据。不能只列线索后让评分者自行平均。例如中心孔可能是拼豆规则的必要条件，局部亮暗只是辅助证据；具体取舍仍由该模板目标决定。

停止细化：测试能区分典型通过、最低合格和失败，并能指出未满足表现开展调优。孔径比例、亮斑位置等只有在影响有效性或实际产生评分分歧时继续细化。跨尺度观察注明尺度；不虚构肉眼测量精度。

## 6. MUST/PREFERRED 与评分

- MUST：假设其他 Rule 都通过，仅此条失败，结果仍不能算有效模板输出。AI 必须记录这个反事实判断的理由。
- PREFERRED：此条失败，结果仍可用且仍属于目标模板，但质量或接近程度下降。
- 待确认不是 PREFERRED；不重要的细节应 OMIT，而非全部收入偏好规则。

AI 提议优先级，UX 确认核心目标与有争议取舍。明显程度、出现频率、Prompt 易写程度均不能直接决定 MUST。

MUST 只定义通过/不通过。PREFERRED 使用 2/1/0：2分完全满足，1分表现尚可，0分违反规则。每一级都必须写成任何人可以直接观察的画面现象，明确对象、位置、数量、边界、颜色、纹理或失败表现；抽象设计术语必须换成这些可观察事实。必要条件任一失败时，不能靠辅助线索补成通过。Rule必须对支持范围内全部输入通用；输入类型、主体数量、类别、背景复杂度、构图和清晰度等条件进入A/B/C测试分层，不写成条件Rule。

评分卡不向测试人员暴露 U 或 N/A。证据不足时应补齐测试材料后再完成该批评分；每条Rule对每张测试图完成一次判断。

整体效果检查放在分类外，不和细项合成额外总分。细项通过而整体偏离时，记录具体遗漏/关系冲突供 UX 判断；不能随意给某个细项扣分。

## 7. DEFINE 执行顺序

1. 收集模板名、参考图、使用场景与运行时输入类型。优先从上下文提取，只问缺失且影响目标的信息。保留既有 3-6 张范围，推荐 4-5 张；本次不改输入数量门槛。
2. 做一次轻量预检：为29项各记一个简短去向，合并候选Rules，记录逐图支持分并计算Rule Set与收敛度。未通过时在这里停止，不写完整Rule卡、Prompt、材料和PDF。
3. 预检通过后复用同一批观察，建立目标卡并补齐正式traversal记录；不得重新分析参考图或复制结论。
4. 形成独立规则卡。通常保持7–10条，最多12条顶层可评分Rules。Criteria来源和参考来源从traversal链接派生；Rule卡不再重复保存evidence。逐图支持只保存在reviewReport.ruleEvidence。必要条件与辅助线索可以完整进入Prompt并映射回同一Rule；只有值得独立评分和独立调优的可选质量维度才拆成PREFERRED Rule。
5. 读取Skill内置Prompt指南，编写初版Prompt并建立Rule映射。指南支持表达，不替代意图或证明生图能力。
6. 完成评分卡与A/B/C材料建议，检查遍历完整、证据可定位、规则无重复、评分边界明确。
7. 直接运行compact_report.py生成当前阶段的一份PDF。FIT/TUNE格式示例只在明确需要时用--include-examples生成。

新数据用 specVersion 0.4；规则 R01...，分类 C1...C5，参考图 REF01...。编号稳定，分类调整不改 Rule ID。既有 0.3 数据仍按原规则读取，不自动改写旧资料。

## 8. Seedream 指南与后续修改

Skill 内置指南：references/seedream-prompt-guide.md，知识版本 2026-09-10.1。该文件随 Skill 打包，已依据官方正文整理 S01-S12 编写知识、任务选择表、Rule 衔接、修改步骤和提交检查。来源页面列明 Seedream 4.0、4.5、5.0 lite，页面更新时间 2026-05-11；读取日期 2026-09-10。日常直接应用包内知识，不要求浏览网页。未知版本或能力记录未覆盖；用户明确要求更新知识时再联网维护。官方链接只用于溯源。

候选 Rule 制定/审查、初版 Prompt、质量门重试、FIT 建议、Final DEFINE、TUNE、补丁、测试人员版本审查均应用指南。同一上下文已加载且未变更时无需机械重复读取；缺少上下文或指南变更时重新读取。原样导出文本不是一次修改。

Prompt 文案是实现假设，不是验收依据。测试人员可以独立改写，AI 不强制接管，也不为满足指南文风重写已有效的 Prompt。每次功能修改记录目标 Rule、修改假设、完整文案和版本，再用真实 Seedream 结果检查修复与退步。

指南不会决定 MUST/PREFERRED，不会证明模型能力。可以使用“水彩”“摄影”等有表达价值的词，验收仍依照可见表现。配置实现、参考图实现与文字表达分开记录。

## 9. 实现与验证边界

0.4 用目标确认与冲突记录代替旧六维均分门槛；这是为解除六维绑定所需的实施约定，不是新设一个更精确的数值指标。旧版门槛仅留在旧版读取分支。

程序可以检查遍历是否漏项、引用是否有效、去向是否连到实际 Rule、等级字段是否缺失、未确认目标是否被错误放行。程序不能仅凭字符串证明语义无重复、观察真实、优先级正确或两个评分者一致。

本轮验收：新格式能校验和生成报告；漏遍历、虚假引用、未确认放行会被拒绝；旧样本仍能读取；R 编号可以进入既有后续阶段格式。真实 Seedream 表现、测试人员独立评分一致性仍需实际验证，不以脚本通过替代。

## 10. 面向 UX 的固定交互结构

模板定义回复包含：模板与输入概览、Rules、Prompt、评分卡、测试材料，以及UX专用REFERENCE。REFERENCE中的可定义性结论由Rule Set成立度和Criteria收敛度计算；Rules依据表解释每条Rule的图片与Criteria来源。已确认目标不再次询问。

Rules依据表列为「Rules｜效果描述｜图片依据｜Criteria依据」。每条Rule都必须出现；依据不足时标为待定。所有结论必须对应真实遍历发现，不能为显得完整随意挂编号。推断、UX确认与可见证据分开标示。

C1...C5 为大项，C1.01 等为固定子项，R01 等为模板规则，REF01 等为参考图。显示编号时同时给出短名称，用户无需记编号。Rule 的关联子项由 traversal 中 RULE/EVIDENCE 引用计算，不另维护一份可能漂移的映射。

覆盖概览按大项显示「有记录子项/应检查子项」，完整时是 C1 5/5、C2 7/7、C3 7/7、C4 5/5、C5 5/5。只能依据已完成的记录生成数字；未完成写实际进度。覆盖包含舍弃、不适用、无法判断等去向，不代表每个子项都必须产生 Rule，也不代表观察已经验证正确。提供完整遍历审计文件供追溯，不强迫 UX 阅读 29 行后才能确认。
